# План переработки игрового чата Metasiberia

Дата: 2026-06-30.

Этот документ фиксирует рабочее направление по новому игровому чату Qt-клиента Metasiberia. Чат считается полноценной игровой подсистемой: интерфейс, сетевой протокол, маршрутизация на сервере, загрузка и скачивание ресурсов, история сообщений, личные сообщения, группы и будущая интеграция игровых действий должны проектироваться вместе.

## 1. Целевой интерфейс

Верхние вкладки:
- `Игроки`
- `Чат`
- `Личные`
- `Группы`
- иконка `Уведомления`
- иконка `Настройки`

Обязательные правила компоновки:
- вкладка `Игроки` показывает только список игроков, без общего чата;
- вкладка `Чат` показывает только общий чат и поле ввода;
- вкладка `Личные` сначала показывает список диалогов/ников, без поля ввода;
- клик по нику в `Личные` открывает конкретный личный диалог с полем ввода;
- `Группы` должна стать отдельной подсистемой групповых диалогов, а не заглушкой в общем чате;
- поле ввода всегда находится внизу, максимально компактное, в стиле Telegram, но в собственной стилистике Metasiberia;
- скрепка и эмодзи находятся внутри поля ввода;
- кнопка отправки только с иконкой, без текста `Чат`, компактная и минималистичная;
- дополнительные действия (`...`) находятся рядом с кнопкой отправки;
- кнопки над полем ввода используются только для быстрых действий отправки, только с иконками и всплывающими подсказками;
- настройки, звук, уведомления, заблокированные игроки, жалобы, закрепление и помощь живут во вкладке `Настройки`.

Сообщения:
- общий чат и личные сообщения не смешиваются визуально;
- входящие личные сообщения дают индикатор на вкладке `Личные` и на конкретном диалоге;
- вкладка `Чат` даёт индикатор непрочитанных сообщений, если пользователь находится не в общем чате;
- сообщения имеют цветовую индикацию: обычные, системные, личные, вложения, ответы;
- ответ на сообщение визуально выделяется цитатой/предпросмотром;
- у каждого сообщения есть быстрые кнопки `Ответить`, `Лайк`, `...`;
- лайки должны стать сетевыми, а не только локальной кнопкой.

Вложения:
- пользователь не выбирает тип файла: выбирает файл, клиент сам прикрепляет и отправляет его;
- все типы файлов поддерживаются как вложения;
- у отправителя сразу есть локальный предпросмотр;
- у получателя файл должен быть реально доступен через серверную систему загрузки/скачивания ресурсов;
- картинки показываются как картинки, не как путь или сырой URL;
- документы, архивы, аудио, видео и прочие файлы показываются как компактные карточки файла с названием, размером и кнопкой открытия/скачивания;
- отправка вложения в личный чат должна идти только в выбранный личный диалог.

## 3. Известные проблемы

- В коде чата встречались жёстко записанные строки с битой кодировкой; весь русский пользовательский текст должен быть нормальным UTF-8 в исходниках или идти через `tr(...)` с корректной кодировкой.
- `PrivateChatMessageID` уже используется клиентом и обрабатывается production-сервером, но поток личных сообщений всё равно нужно проверять двумя клиентами после каждой правки маршрутизации.
- Состояние вкладки `Личные` хрупкое: список диалогов и открытый диалог делят одну и ту же раскладку и общее хранилище сообщений.
- `privateChatPeerFromPlainText()` распознаёт английские `Private to/from`, но не полностью обрабатывает русские подписи.
- Локальный предпросмотр вложения сейчас появляется раньше сетевого подтверждения; удалённым клиентам нужен реально загруженный ресурс, доступный через сервер.
- Вложения сейчас встроены в текст сообщения; краткосрочно это допустимо, но дальше нужно перейти к структурированным метаданным в протоколе.
- Группы ещё не реализованы.
- Лайки и реакции сейчас локальные в интерфейсе, не сохраняются и не рассылаются по сети.
- История сообщений в основном живёт в памяти интерфейса.

## 7. Канонические требования к новой подсистеме чата

Этот раздел фиксирует полное ТЗ на развитие чата. Его нельзя реализовывать хаотично одной большой правкой: сначала вводятся модели данных и совместимый протокол, затем серверная синхронизация, затем интерфейсные возможности.

### 7.1 Личные сообщения

Вкладка `Личные` должна показывать список диалогов, а не список игроков.

Диалог:
- существует независимо от текущего онлайна собеседника;
- не исчезает, если игрок вышел из игры;
- сортируется по времени последнего сообщения;
- хранит `peerId`, последнее сообщение, время последнего сообщения, количество непрочитанных и историю;
- открывается кликом по строке диалога;
- только после открытия конкретного диалога показывает поле ввода.

Отдельный диалог `Избранное`:
- всегда доступен пользователю;
- принимает сохранённые сообщения из общего чата, личных сообщений и групп;
- работает как личная папка сохранённых сообщений по модели Telegram.

Анонимусы:
- не могут первыми писать зарегистрированным пользователям;
- не могут писать в общий чат;
- не могут писать в группы;
- могут отвечать только в уже открытом диалоге, если зарегистрированный пользователь написал первым;
- имеют уникальный внутренний `SessionID`, не равный постоянному пользовательскому `UID`.

### 7.2 Сетевой протокол сообщений

Личные сообщения должны использовать отдельный тип пакета. Текстовые маркеры внутри общего чата запрещены для новой реализации.

Минимальная структура личного сообщения:
- `senderId`;
- `receiverId`;
- `messageId`;
- `timestamp`;
- тип сообщения;
- список вложений;
- `parentMessageId` для ответа;
- реакции;
- статус доставки.

Этап совместимости:
- текущий `Protocol::PrivateChatMessageID` использовать как первый реальный путь для личных сообщений;
- старый текстовый запасной маркер оставить только временно для старых клиентов/серверов;
- после проверки рабочего сервера удалить зависимость интерфейса от строк `Private to/from`.

### 7.3 История, поиск и пагинация

История не должна жить только в памяти `MainWindow`.

Нужно добавить:
- сохранение истории сообщений;
- восстановление истории после перезапуска клиента;
- постраничную загрузку старых сообщений;
- поиск по тексту;
- поиск по пользователю;
- поиск по дате;
- поиск по типу сообщения;
- поиск по вложениям;
- единый глобальный поиск по игрокам, сообщениям, группам и файлам.

### 7.4 Вложения

Порядок отправки вложения:
- пользователь выбирает файл без выбора типа;
- клиент сразу показывает локальный предпросмотр;
- клиент загружает файл на сервер;
- сервер возвращает `ResourceID` или совместимый серверный URL ресурса;
- сообщение содержит только идентификатор ресурса и метаданные, а не локальный путь;
- получатель автоматически скачивает ресурс и видит файл в сообщении.

Поддерживаемые типы:
- изображения;
- документы;
- архивы;
- видео;
- аудио;
- голосовые сообщения;
- любые прочие файлы как обычные вложения.

Отображение:
- картинки показываются миниатюрами;
- остальные файлы показываются карточкой с названием, размером, типом и действием открытия/скачивания;
- путь вида `C:\...` или `file://...` не должен попадать в сообщение для другого клиента.

### 7.5 Ответы, реакции и действия над сообщением

Ответ на сообщение:
- хранит `parentMessageId`;
- показывает автора исходного сообщения;
- показывает короткий фрагмент текста;
- по клику на цитату прокручивает чат к оригиналу.

Сетевые реакции:
- поддержать `👍`, `❤️`, `😂`, `😮`, `😢`, `👎`;
- каждая реакция синхронизируется через сервер;
- реакции должны сохраняться в истории.

Контекстное меню сообщения:
- `Ответить`;
- `Цитировать`;
- `Скопировать`;
- `Переслать`;
- `В избранное`;
- `Закрепить`;
- `Удалить`;
- `Пожаловаться`.

### 7.6 Непрочитанные, статусы и очередь

Счётчики непрочитанных:
- вкладка `Чат`;
- вкладка `Личные`;
- вкладка `Группы`;
- каждый личный диалог;
- каждая группа.

Индикатор печати:
- локально показывает `Пользователь печатает...`;
- передаётся по сети отдельным событием;
- не должен создавать обычное сообщение в истории.

Статусы доставки:
- `Отправляется`;
- `Доставлено серверу`;
- `Получено получателем`;
- `Прочитано`;
- `Ошибка отправки`.

Очередь сообщений:
- при потере соединения сообщения остаются в локальной очереди;
- после восстановления соединения очередь автоматически отправляется;
- пользователь видит статус и может повторить отправку вручную.

Автоскролл:
- если пользователь читает историю, новые сообщения не сбрасывают позицию вниз;
- появляется кнопка `Новые сообщения`;
- автоскролл включается только если пользователь уже находился внизу.

### 7.7 Игроки, роли, профиль и друзья

Модель игрока должна хранить:
- `UID`;
- ник;
- роль;
- статус;
- онлайн;
- аватар;
- цвет;
- бейдж;
- текущий мир;
- группу;
- пинг.

Роли и права должны приходить с сервера и обновляться динамически.

Роли:
- владелец;
- администратор;
- модератор;
- модератор мира;
- особый статус;
- игрок;
- анонимус;
- бот.

Профиль игрока:
- `UID`;
- аватар;
- роль;
- уровень;
- дата регистрации;
- парселы;
- достижения;
- друзья;
- группы.

Друзья:
- добавить;
- удалить;
- запрос ожидает подтверждения;
- онлайн-статус;
- избранные друзья.

### 7.8 Группы

Группы должны стать отдельной подсистемой, а не UI-заглушкой.

Минимум:
- создание группы;
- приглашение;
- удаление;
- выход;
- передача владельца;
- роли;
- история;
- непрочитанные;
- настройки группы;
- отдельная маршрутизация сообщений на сервере.

### 7.9 Голос, звонки и шифрование

Голосовые сообщения:
- отдельная кнопка микрофона;
- кодек Opus;
- отправляются как обычное вложение;
- сохраняются в истории как отдельный тип сообщения.

Аудиозвонки:
- не писать собственную реализацию WebRTC;
- подготовить сигналинг;
- статусы входящего и исходящего звонка;
- место в интерфейсе.

Видеозвонки:
- подготовить архитектуру и место в интерфейсе;
- реализацию оставить расширяемой.

Шифрование:
- минимум TLS для сетевого соединения;
- предусмотреть будущий переход на сквозное шифрование личных сообщений.

### 7.10 Жалобы, модерация, блокировки и закрепления

Жалоба отправляется:
- на игрока;
- на сообщение;
- на вложение;
- с обязательной причиной.

Интерфейс модераторов:
- удаление сообщений;
- мьют;
- кик;
- бан;
- история действий.

Заблокированные игроки:
- не могут писать в личные сообщения;
- их сообщения скрываются;
- их приглашения игнорируются.

Закреплённые сообщения:
- общий чат;
- группы;
- личные сообщения.

### 7.11 Локализация и качество интерфейса

Все пользовательские строки должны идти через `tr()` или другой существующий механизм локализации Qt.

Запрещено:
- битая кодировка;
- смешивание русского интерфейсного текста с английскими черновыми строками;
- текстовые кнопки там, где по дизайну нужна компактная иконка;
- смешивание общего чата, личных сообщений и групп в одном списке.

Разрешено оставлять на английском:
- имена классов;
- имена функций;
- имена файлов;
- константы протокола;
- буквальные строки, которые нужны для совместимости со старым протоколом.

## 8. Порядок внедрения без регрессий

Очередь работ:
- стабилизировать текущий Qt-интерфейс и убрать битую кодировку;
- перевести отправку личных сообщений на `Protocol::PrivateChatMessageID`;
- ввести клиентскую модель диалогов, не завязанную на онлайн-список игроков;
- отделить список диалогов `Личные` от открытого личного чата;
- закрепить реальные вложения через серверный ресурсный путь;
- добавить счётчики непрочитанных;
- добавить сохранение локальной истории;
- затем расширять протокол под `messageId`, `parentMessageId`, реакции, статусы доставки и группы.

Каждый этап должен собираться и проверяться отдельно на двух клиентах.
