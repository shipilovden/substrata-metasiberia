# Orchestration for Metasiberia

## Назначение

Главный агент — **Orchestrator**. Он отвечает за понимание запроса, границы, начальное исследование, решение о делегации, интеграцию, проверку и итоговый отчёт. Оркестрация — средство снизить риск и время, а не обязательный ритуал.

## Решение о делегации

Работать одному, если изменение локально, понятен owner и проверка узкая. Делегировать, когда независимое исследование уменьшает объём контекста, реализация разбивается по непересекающимся границам или изменение требует независимого review/verification.

Не делегировать одну строку, косметическую правку или несколько агентов в один файл. Не запускать параллельные задания, если один результат нужен для понимания другого.

## Логические роли

### Explorer

Read-only исследует строго заданную область: symbols, owners, consumers, существующий паттерн, риски и минимальный следующий шаг. Не меняет файлы и не пересказывает репозиторий.

Возврат:

```text
FINDINGS
RELEVANT FILES
DEPENDENCIES
EXISTING PATTERN
RISKS
RECOMMENDED NEXT STEP
```

### Implementer

Реализует локально ограниченное изменение. Сначала читает текущую реализацию и ближайший аналог, делает минимальный diff, не расширяет scope и выполняет обусловленные проверки.

### Strong Implementer

Используется только для сложной архитектурной, network, rendering, concurrency, persistence или многомодульной задачи. Это логическая роль: не предполагает отдельную модель или скрытый configuration key.

### Reviewer

Независимо анализирует готовый diff, а не повторно реализует задачу. High-risk изменения не завершаются без review по [REVIEW_PROTOCOL.md](REVIEW_PROTOCOL.md).

### Verification agent

Определяет, что реально можно проверить, выполняет согласованные проверки либо честно фиксирует ограничения. Не объявляет успех только по чтению diff.

## Рабочий цикл

1. Orchestrator уточняет цель, scope, риск и критерии готовности.
2. Выполняет быстрый поиск по docs/code. При необходимости поручает Explorer независимые области.
3. Строит task graph: files, dependencies, порядок и conflict boundaries.
4. Делегирует реализацию только непересекающимся областям или выполняет её сам.
5. Интегрирует результат и запускает целевые проверки.
6. Для high-risk изменений запускает Reviewer после реализации.
7. Исправляет только подтверждённые существенные замечания, затем выполняет final verification.

## Параллелизм

Допустим для независимых read-only исследований или файловых областей без общего владельца. Перед стартом Orchestrator фиксирует, что файлы не пересекаются и результаты не имеют сильной последовательной зависимости. При сомнении — последовательная работа.

## Реальная поддержка Codex

Локальный Codex CLI `0.146.0-alpha.9.2` сообщает stable effective feature `multi_agent`, но его публичная CLI/help не предоставляет конфигурацию именованных ролей, лимитов агентов, чистого контекста или отдельных model/reasoning settings для роли. Поэтому роли, контракты и gates реализованы этими инструкциями; использовать доступный в конкретной поверхности Codex multi-agent механизм можно только в его реально предоставленном виде.
